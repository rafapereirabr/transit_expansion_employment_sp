# Interview me

1. Read the project objective, `MEMORY.md`, and relevant `BACKLOG.md` section.
2. Ask only questions whose answers materially change the estimand, audience, product, data,
   identification strategy, deadline, or verification. Prefer one short batch.
3. Distinguish confirmed requirements from assumptions and open blockers.
4. Write `quality_reports/specs/YYYY-MM-DD_description.md` using
   `templates/requirements-spec.md` (create the directory if needed).
5. Separate MUST, SHOULD, and MAY requirements and define measurable success criteria.
6. Present the specification for approval. Do not begin the analysis or silently choose a causal
   estimand while a material aspect is blocked.
